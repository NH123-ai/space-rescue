          任务简报 / MISSION BRIEFING

          空间中有 N 个待救援目标。目标位置随时间低速漂移， 救援队位于坐标系原点，飞船速率恒定 10.0， 每经过 5.0 个时间单位可刷新一次目标坐标。

          每个目标都有最长生存时间，一旦超时即救援失败。本演示把 C 程序算出的 “救援顺序 + 各航段时刻”还原为可拖拽的 3D 过程动画。

          操作

          • 空格 播放 / 暂停

          • R 回到起点
          • C 自动环绕开关
          • 拖拽 旋转视角 · 滚轮 缩放

          关于这个项目

          这是《软件设计思想与方法》综合程序设计五的作业：太空救援问题。 空间里有若干个待救援目标，位置随时间低速漂移，每个目标有最长生存时间； 救援队从坐标原点出发，救完不用返回。要解决的是“先救谁、什么时候到”， 再把整个救援过程做成能看懂、能回放的演示。

          页面上看到的数字是怎么来的

          救援顺序和各段航程时刻由 C 程序算好，导出成一份 trace.js； 这个页面只负责渲染，不做任何求解。所以时间轴可以随便拖、倍速、切换方案， 画面永远是同一份数据的不同时刻。

          四种救援方案

          • 最近邻贪心 NN：每次挑离飞船最近的目标，快，但容易把紧迫的目标拖死。
          • 生存时间优先 EDF：先救生存余量最小的，更贴合题目约束，但航程往往更长。
          • 2-opt 局部搜索：在贪心解上反转航段做局部改进，质量和耗时的折中。
          • 回溯搜索：小规模时求最优，规模大了换成带剪枝的版本（节点有上限）。

          右侧「算法对比」面板里能看到每种方案的获救数、总航程、搜索节点数和耗时， 点一下就会把演示航线换成那一套。

          两个实现上的细节

          飞行时间不是“距离 ÷ 速度”直接算的：目标是动的，飞过去这段时间它也在跑， 真正要解的是拦截方程 |p0 + v·τ − ship| = SPEED·τ，展开成一元二次方程取正根。 另外整个演示的数据量很小（9 个目标约 6 KB），因为页面不存逐帧坐标， 而是按“目标匀速漂移 + 飞船分段匀速”这两条规律自己把画面算出来。

          渲染是手写的 Canvas 2D 三维投影，没有引 three.js 之类的库，整站断网也能跑。
