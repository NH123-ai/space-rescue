## 二、换成你自己的场景（需要编译一次）

### 情况 A：电脑有 gcc / MinGW / Dev-C++

双击 `build.bat`（看到“编译成功”即可），然后在本目录打开命令行：

```bat
space_rescue.exe --trace web
```

再刷新浏览器里的 `index.html`。

> 注意：`trace.js` 是 C 程序生成的**静态文件**，换场景后必须重新生成并刷新页面，
> 网页不会自己去跑算法。

### 情况 B：电脑没有编译器

- 装 MinGW-w64 或 Dev-C++ 后再走情况 A；或用 VS2022 新建空工程，
  把这些文件加进去编译（`main.c` `data_module.c` `algorithm_module.c` `viz_module.c`）。
- 暂时只想演示：直接用自带数据（第一节），或让组员编译好把 `web\trace.js` 发给你。
- 也可以用 Python 参考实现临时生成一份：
  `python tools\gen_trace_reference.py --n 9 --scenario tight --seed 8 --out web`

### 常用场景命令

```bat
space_rescue.exe --trace web                              :: 标准 9 目标
space_rescue.exe --n 12 --scenario tight --seed 8 --trace web   :: 12 目标、必有牺牲（答辩亮点）
space_rescue.exe --n 10 --scenario cluster --seed 23 --trace web :: 星团场景
space_rescue.exe --menu                                   :: 交互式反复换场景演示
space_rescue.exe --test                                   :: 跑 8 个测试用例（报告“软件测试”用）
space_rescue.exe                                          :: 只打印控制台报告
```

## 三、答辩现场 5 步（约 3 分钟）

1. 双击 `space_rescue.exe`（或命令行 `space_rescue.exe --trace web`）→ 控制台先出报告：
   目标清单、推荐方案、航段甘特图、算法对比表。
2. 双击 `web\index.html` → 点“开始演示”，讲漂移目标 + 生存环缩短 + 飞船对接。
3. 空格暂停，拖时间轴回退，指着某个目标说“这里剩余生存还有多少”。
4. 切右侧“算法对比”，依次点 NN / EDF / 2-opt / 回溯，讲航程和搜索节点的差距。
5. 换极端场景（`--n 12 --scenario tight --seed 8`）刷新页面，展示红色牺牲目标，
   收尾点“导出 PNG”存一张最终帧。

## 六、单独调试视觉模块（viz_test）

`viz_test\` 是专门给队员 C 用的测试台：**只链接 `viz_module.c`**，数据来自
`mock_data.c` 手工构造，改样式不用跑完整求解流程。

```bat
cd viz_test
build_test.bat            :: 编出 viz_test.exe（独立模式；full 参数则连真实模块联调）
viz_test.exe              :: 跑 96 条断言，结尾给出“通过 X 条 / 失败 Y 条”
viz_test.exe --demo        :: 交互沙箱：键 5/6 调目标数与种子，立刻重印仪表盘/俯视图/过程模拟
viz_test.exe --emit out    :: 生成 out/trace.js，浏览器打开 preview.html 看 3D 效果
```

断言覆盖：中文列宽对齐与 UTF-8 不切断、推荐方案选择规则、仪表盘各段内容、
ASCII 俯视图的除零/重叠/零目标、过程模拟**不修改入参**（防坐标漂移回归）、
trace 导出的 JSON 结构/初始坐标/空方案/零目标/数值格式/不可写路径等。

`preview.html` 是 `web/index.html` 的自动副本（`python sync_preview.py` 重新生成），
所以调试所见即正式页面所见，不会出现“两套 UI 漂移”。

## 七、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 网页打开是“未找到救援轨迹数据” | `web\trace.js` 丢了 → 重新 `space_rescue.exe --trace web` |
| 网页数据和 C 报告对不上 | 忘了刷新浏览器（`Ctrl+F5`），`trace.js` 是静态文件 |
| 控制台中文乱码 | 先 `chcp 65001`，或加 `--no-color` 把输出重定向到文件看 |
| `build.bat` 说找不到 gcc | 装 MinGW-w64/Dev-C++，或直接用 VS2022 编译；不影响网页演示 |
| EasyX 版编译失败 | 没装 EasyX 而已，`build.bat easyx` 是可选路径，网页版不受影响 |
| 时间轴拖不动 / 播放很快结束 | 极端场景总时长更短，属正常；用 `0.25×` 慢放看细节 |
| `viz_test.exe --emit` 后网页还是旧数据 | `preview.html` 读的是 `viz_test\out\trace.js`；确认 `out\` 里有新文件后 `Ctrl+F5` |

## 八、如果你想改

- **改视觉模块（表格/文案/ASCII 图）**：改 `viz_module.c` 后先跑 `viz_test\viz_test.exe`，
  96 条断言全过再回到上级目录 `build.bat` 联调
- **改界面配色/布局**：`web\styles.css`（顶部 `:root` 里是语义色变量）
- **改 3D 场景画法**：`web\app.js` 里 `drawTargets` / `drawShip` / `drawRoute` / `drawEffects`
- **改场景生成规则**：`data_module.c` 的 `gen_scenario`（距离范围、漂移速度、生存时间）
- **改算法**：`algorithm_module.c`，新增策略后只要填一个 `RoutePlan`，
  再在 `main.c` 的 `run_all_plans` 里加一行，网页端会自动多出一个对比方案卡片
- **加实时推送（现场改参数即时刷新）**：需要给 C 加一个极简 HTTP/SSE 服务，
  这是 `docs\队员C可视化升级说明.md` 第九节列的后续方向。
