## 二、开发环境与总体约定（补充两条）

- 全部成员共用同一个头文件 `space_rescue.h`，结构体、宏定义、函数声明统一在该头文件中，
  禁止个人私自修改已有字段名、函数名与参数表；**如需扩展只能在结构体末尾追加字段，
  并在本节“接口变更登记”里登记**。
- 模块间只通过 `RescueData` / `RoutePlan` 指针传递数据，不使用全局变量跨模块传参。
- 依赖方向单向：数据模块无外部依赖 → 算法模块 / 可视化模块依赖数据模块 → 主程序与测试模块依赖其余三者。
- 四人各自交付独立的 `.c` 文件，最后由主程序负责人统一编译联调。
- **构建与演示口径统一**：控制台版为“必须有”的交付形态（任何电脑 `gcc` 一条命令即可跑通）；
  图形演示用网页版（`web/index.html`，零依赖、断网可跑、双击即开）；
  EasyX 版作为“大纲知识点对照”的可选实现，需本机安装 EasyX 才编译。

### 接口变更登记（v1 → v2，仅追加）

| 位置 | 追加内容 | 用途 | 提出人 |
| --- | --- | --- | --- |
| `Target` | `double vx, vy, vz;` | 目标漂移速度（题目要求位置随时间变化） | C |
| `Target` | `double life_left;` | 仿真中剩余生存时间（压力条与状态判断） | C |
| `RescueData` | `total_distance, saved_count, dead_count, algo_used` | 结果汇总，供输出与界面读取 | C |
| `RescueData` | `origin_x, origin_y, origin_z` | 救援基点由“写死原点”改为可配置 | C |
| `RescueData` | `seed, scenario` | 场景可复现并在界面标注 | C |
| 新增类型 | `RoutePlan` | 一条完整方案：顺序 + 每段时刻/距离 + 节点数 + 耗时 + 可行性 | B+C |
| 新增函数 | 见第三节“可视化模块 v2” | 控制台仪表盘 / trace 导出 / ASCII 俯视图 | C |

> 兼容性：v1 的字段名、字段顺序、函数签名全部未改，A/B/D 的旧代码可以原样编译。

## 三、共用接口定义（space_rescue.h v2 摘要）

```c
// 宏定义
#define MAX_TARGET_NUM 12    // 最大待救援目标数量，回溯规模不宜过大
#define SPEED 10.0           // 救援飞船速度（距离/时间单位）
#define UPDATE_INTERVAL 5.0  // 坐标刷新间隔 t

// 目标结构体：三维坐标 + 漂移速度 + 最长生存时间 + 获救状态
typedef struct {
    double x, y, z;         // 当前三维坐标
    double life_max_time;   // 最长生存时间，超过则救援失败
    int    is_saved;        // 0 未救援，1 已救援
    double save_time;       // 实际被救援时刻
    /* v2 追加 */
    double vx, vy, vz;      // 漂移速度向量
    double life_left;       // 剩余生存时间
} Target;

// 全局救援数据
typedef struct {
    Target target_list[MAX_TARGET_NUM];
    int    target_count;
    double total_time;
    int    best_seq[MAX_TARGET_NUM];
    int    find_success;
    /* v2 追加 */
    double total_distance;  int saved_count, dead_count, algo_used;
    double origin_x, origin_y, origin_z;
    unsigned seed;  int scenario;
} RescueData;

// 单条救援方案的完整统计（v2 新增，算法模块输出 / 可视化模块输入）
typedef struct {
    int    seq[MAX_TARGET_NUM]; int len;
    double leg_t[MAX_TARGET_NUM], leg_d[MAX_TARGET_NUM];
    double length, finish_time;
    int    saved, dead, feasible;
    long   nodes;        // 搜索节点数（复杂度评价）
    double elapsed_ms;   // 计算耗时
    int    algo;         // ALGO_NN / ALGO_URGENCY / ALGO_BACKTRACK / ALGO_2OPT
} RoutePlan;
```

各模块函数（完整签名见源码 `space_rescue.h`）：

- **A 数据模块**：`read_target_data` / `print_target_info` / `calc_3d_distance` / `update_target_pos`
  ｜ v2：`gen_scenario`（可复现场景生成）、`reset_target_states`、`target_pos_at`（漂移解析式）
- **B 算法模块**：`tsp_greedy` / `tsp_backtrack` / `check_time_constraint`
  ｜ v2：`plan_nearest` / `plan_urgency` / `plan_2opt` / `plan_backtrack` / `plan_simulate` / `plan_apply` / `plan_name`
- **C 可视化模块**：`draw_console_sim`
  ｜ v2：`viz_render_report`（控制台仪表盘）/ `viz_write_trace`（导出 web/trace.js）/ `viz_draw_ascii_map`（ASCII 俯视图）
  ｜ 可选 EasyX：`init_easyx_window` / `draw_3d_projection` / `run_rescue_animation`
- **D 主程序**：`print_result` / `run_test_case` / `main`（命令行 + 菜单 + 测试集）

## 队员 C 分工（升级版）

**模块名称**：可视化演示模块（`viz_module.c`，可选 `viz_easyx_optional.c`）

**设计原则**：C 端只负责“算得准、导得全”，渲染层负责“看得懂、讲得清”。
可视化不再和算法耦合——同一份 `RescueData` / `RoutePlan`，可以驱动控制台、EasyX、网页三种渲染器。

### 交付物

| # | 文件 | 内容 | 验收标准 |
| --- | --- | --- | --- |
| C1 | `viz_module.c` | 控制台仪表盘（ANSI 彩色：目标表、状态压力条、航段甘特图、算法对比表、推荐方案） | `space_rescue.exe` 直接运行即输出，表格对齐、中文不乱位 |
| C2 | `viz_module.c` | `viz_draw_ascii_map`：XZ 俯视图，标出基点、目标编号、已获救标记 | 无彩色终端也能演示空间分布 |
| C3 | `viz_module.c` | `viz_write_trace`：导出 `web/trace.json` + `web/trace.js`（场景 + 4 种方案 + 事件流） | 文件可被网页直接加载，字段与 `README.md` 数据契约一致 |
| C4 | `web/index.html` `styles.css` `app.js` | 3D 救援演示：星域场景、漂移目标与生存环、飞船航迹与光锥、对接/牺牲特效、坐标刷新扫描环 | 三种分辨率下无报错、目标绘制位置正确、左右面板与时间轴不重叠 |
| C5 | `web/app.js` | HUD 与交互：任务时钟、四项实时指标、播放/倍速/单步、可拖拽时间轴、目标列表自动排序、算法对比条、事件日志跳转、视角操作、PNG 导出、深链接 | 空格暂停、拖时间轴回放、点击日志跳转、点算法卡片切换航线均生效 |
| C6 | `viz_easyx_optional.c` | EasyX 原生动画（等轴测投影、生存条、飞船三角） | 定义 `EASYX` 时编译通过（需装 EasyX），与网页版同数据 |
| C7 | `docs/队员C可视化升级说明.md` | 方案说明、接口登记、答辩脚本、评分点对照、验证记录 | 可直接并入实验报告“详细设计/测试”章节 |
| C8 | `viz_test/` | 视觉模块独立测试台：只链接 `viz_module.c`，96 条断言 + 交互沙箱 + 外观预览页 | `viz_test.exe` 全过（退出码 0）；`--demo` 可改场景即时看输出；`--emit out` 后用 `preview.html` 预览 3D |

### 组员 C 与其他人的接口

- 向 **A 要**：`RescueData`（目标坐标、速度、生存上限、场景 seed）。
- 向 **B 要**：`RoutePlan[]`（每方案的 `seq / leg_t / leg_d / length / nodes / elapsed_ms`）。
  注意：可视化**不做任何路径计算**，只做坐标还原与呈现。
- 给 **D 用**：`main.c` 里依次调用 `viz_render_report`、`plan_apply` + `print_result`、
  `draw_console_sim`、`viz_draw_ascii_map`、`viz_write_trace`。
- 若 A/B 改动结构体：只允许在末尾追加，并同步本页“接口变更登记”。

### 性能与健壮性要求（组员 C 自检项）

- 网页端 1080p 稳定 60 FPS（光晕使用离屏精灵缓存，HUD 列表按帧节流）。
- `viz_write_trace` 在目录不存在时自动创建；写入失败给出明确提示且不影响主流程。
- 控制台表格按“显示列宽”（中文 2 列）补齐，保证不同终端不错位。
- 所有渲染函数对 `NULL` 指针、空方案数组、单目标/零航段情况有兜底。

## 演示与测试口径（与文档其他部分保持一致）

```bat
build.bat                          :: 编译
space_rescue.exe --trace web       :: 生成 web/trace.js 并打印控制台报告
start web\index.html               :: 浏览器演示（双击亦可）

space_rescue.exe --test            :: 8 个内置测试用例（含必牺牲场景）
space_rescue.exe --n 12 --scenario tight --seed 8 --trace web   :: 牺牲场景演示
space_rescue.exe --menu            :: 交互式反复演示（满足“一次运行多次演示”）
```

**测试用例与基准值**（`--test` 会逐条判定 PASS / 偏差）：
1 单目标 1/1；2 标准 9 目标 9/9；3 紧急 9 目标 9/9；4 星团 10 目标 10/10；
5 大尺度 8 目标 8/8；6 满规模 12 目标 12/12；7 随机 11 目标 11/11；8 极端紧迫 12 目标 9/12。

## 附：为什么“网页渲染”也符合大纲

- 大纲对扩展功能的要求是“**算法效率高、功能完整、可演示**，包括对比分析不同方法、
  评价效率、**界面及动画设计**、设置目标初始状态、模拟演示救援过程、给出最佳救援方法”，
  并没有限定必须用 EasyX 绘制；大纲同时写明“华为智能基座班的学生可开发**在线游戏模式**”，
  即鼓励 Web 形态。
- 大纲核心知识点列出“界面设计，EasyX，或 QT 或 VS 的对话框设计”，
  因此我们**保留 EasyX 实现**（`viz_easyx_optional.c`）作为知识点对照，
  网页版作为更完整的演示形态，两者共用同一份 C 数据结构，不构成“两套实现”。
- 核心算法仍由 C 完成（拦截时间解析解、四种排序策略、回溯剪枝），网页只做渲染与交互，
  不违背“使用 C 语言”的课程要求。
