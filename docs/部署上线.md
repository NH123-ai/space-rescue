# 做成公开网站：任何人输网址就能玩

> 现状：可视化是纯前端的（`web/` 目录 = 一个静态站点），数据由 C 程序预先生成。
> 所以**不需要服务器、不需要数据库、不需要域名**，白嫖静态托管就能上线，
> 别人打开网址就能拖时间轴、切场景、看 3D 救援过程。

---

## 一、为什么可以直接上线（原理）

```
C 程序（本地运行一次）                      浏览器（别人访问你的网址）
  space_rescue --trace-all web/traces   →   web/index.html
        ↓                                    ├─ boot.js        按 ?trace=xxx 选数据
  web/traces/catalog.js（场景清单）            ├─ traces/<key>/trace.js（该场景数据）
  web/traces/<key>/trace.js（场景数据）        ├─ app.js         3D 渲染 + HUD + 时间轴
                                               └─ styles.css
```

站点里**没有任何服务端逻辑**：所有计算都在浏览器里（把“目标等速漂移 + 飞船分段匀速”
这两条解析规律还原成动画）。因此任何静态托管都能跑，且免费额度足够。

代价（很重要）：**场景是预先生成好的**，别人只能在你提供的 6 个场景里切换，
不能自己改目标数/种子。要做到“随便输参数即时生成”，见文末第五节。

## 二、上线前：先生成站点数据

**一条命令即可，脚本会自动选数据来源**：

```bat
cd /d "D:\dshworkplace\C analyze\space_rescue"
tools\build_site.bat
```

| 情况 | 脚本行为 | 界面徽标 |
| --- | --- | --- |
| 队友 A/B/D 的模块已就绪（能编出 `space_rescue.exe`） | `space_rescue --trace-all web/traces` | “数据：正式模块” |
| **还没就绪（当前就是这种状态）** | 退回 `viz_test --emit-all web/traces`（测试桩数据） | “数据：测试桩（等队友模块接入）” |

想强制指定：`tools\build_site.bat full` / `tools\build_site.bat mock`。

> 现在站点跑的是**测试台数据**：场景由 `viz_test/mock_data.c` 手工构造，
> 四条方案分别标注为“最近邻贪心（测试桩）/ 生存优先贪心（测试桩）/
> 反向顺序基线（测试桩）/ 交替顺序基线（测试桩）”，不会冒充队友的真实算法。
> 队友代码交付后重跑一次 `tools\build_site.bat` 即自动切换，详见 `docs/接入队友模块.md`。

输出：

```
站点数据（测试桩）已生成：6/6 个场景
  目录：…\space_rescue\web\traces
  清单：…\space_rescue\web\traces\catalog.js
  切到正式数据只需：space_rescue.exe --trace-all web/traces（前端不用改）
```

生成 6 个场景（正式与测试台两边 key 一致；要加场景：
正式见 `main.c` 的 `g_site_scenes[]`，测试桩见 `viz_test.c` 的 `g_mock_scenes[]`）：

| key | 场景 | 特点 |
| --- | --- | --- |
| `standard` | 标准场景 · 9 目标 | 默认打开，全部获救 |
| `tight` | 紧急场景 · 12 目标 | 生存时间紧，切到基线方案会大量牺牲（红色） |
| `cluster` | 星团场景 · 10 目标 | 目标聚成一团、离基点远 |
| `wide` | 大尺度场景 · 8 目标 | 散布范围极大 |
| `random` | 随机场景 · 11 目标 | 完全随机 |
| `max` | 满规模 · 12 目标 | 回溯搜索规模上限 |

本地先自测（不要直接双击 html 就以为没问题，用 http 更接近线上）：

```bat
cd /d "D:\dshworkplace\C analyze\space_rescue\web"
python -m http.server 8777
:: 浏览器打开 http://127.0.0.1:8777/index.html
:: 切场景：http://127.0.0.1:8777/index.html?trace=tight
```

## 三、方案 A：GitHub Pages（推荐，免费、自带 CI）

### 1. 建仓库并推送

```bat
cd /d "D:\dshworkplace\C analyze\space_rescue"
git init
git add .
git commit -m "太空救援问题：C 求解 + 3D 可视化公开演示"
git branch -M main
git remote add origin https://github.com/<你的用户名>/space-rescue.git
git push -u origin main
```

### 2. 开启 Pages

- 仓库 → **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**；
- 已自带工作流 `.github/workflows/pages.yml`（**不在云端编译 C**：只做 Node 数据自检 + 发布 `web/`，推送即部署）；
- 等 Actions 跑绿（约 1 分钟），地址是：

```
https://<你的用户名>.github.io/space-rescue/
```

分享时可以直接给带场景的链接：

```
https://<你的用户名>.github.io/space-rescue/?trace=tight
```

### 3. 之后改了内容怎么更新

```bat
cmake-build-debug\space_rescue.exe --trace-all web/traces
git add -A && git commit -m "更新场景数据" && git push
```

（工作流里也带了兜底：如果仓库里没有 `web/traces/catalog.js`，CI 会用 gcc 现场编译并生成。）

## 四、方案 B / C：Vercel、Netlify（拖拽或连仓库都行）

两个平台都只要“**发布目录 = `web`**、无构建命令”这一条信息，仓库里已放好配置：

| 平台 | 怎么做 | 备注 |
| --- | --- | --- |
| **Vercel** | 新建项目 → 选仓库 → 框架选 **Other** → Root/Output 保持 `web`（`vercel.json` 已声明 `outputDirectory`） | 免费、给 `xxx.vercel.app` 域名、支持自定义域名 |
| **Netlify** | 新建站点 → 连仓库（`netlify.toml` 已声明 `publish = "web"`），或直接把 `web` 文件夹**拖进** Netlify Drop | 拖拽方式最快，30 秒上线 |
| **Cloudflare Pages** | 连仓库 → Build output directory 填 `web`，构建命令留空 | 国内访问速度通常更好 |

> 国内访问小提示：GitHub Pages 的 `*.github.io` 有时不稳定，给同学演示可以用
> Cloudflare Pages 或 Vercel；也可以用 Gitee Pages（需实名与仓库公开）。

## 五、想要“随便输参数即时生成”？两条升级路线

现在数据是预先算好的。若要做到“访问者输入目标数 / 场景 / 种子，立刻出新局面”，
本质上得让**浏览器或服务器能跑 C 算法**，二选一：

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. C 编译成 WebAssembly**（推荐） | 用 Emscripten 把 `algorithm_module.c` + `data_module.c` 编成 `rescue.wasm`，`app.js` 里调用它算 `RoutePlan[]`，再交给现有渲染层 | 纯静态托管仍可用（依旧免服务器、免费用），算法仍是同一份 C 代码，答辩讲“C 核心跑在浏览器里”很有说服力 | 需要装 Emscripten 工具链（emsdk），CMake/GCC 换一套编译目标；`viz_console_init`/文件写入等平台相关代码要加 `__EMSCRIPTEN__` 分支 |
| **B. 带后端的小服务** | 前端 POST 参数 → 服务器调用 `space_rescue.exe`（或直接用 C 写个 20 行的 HTTP 服务）→ 返回 `trace.json` | 改动最小，C 代码不动 | 需要一台常开的服务器 / 云函数（免费额度有限），运维与跨域都要处理 |

两者我会推荐 A：既保留“纯静态、白嫖托管”，又真正做到“任意参数即时可玩”，
也更贴合大纲里“华为智能基座班可开发在线游戏模式”的扩展方向。
需要我把它做出来的话说一声，我按 `emsdk + 一个 wasm 构建目标 + 前端参数面板`的方案改。

- [ ] 分享一个带 `?trace=tight` 的链接给同学，确认他那边是“紧急场景 · 12 目标”
- [ ] `/index.html` 的 `<title>` 与 `og:` 标签显示正常（微信/QQ 分享会取这些）
- [ ] 若用自定义域名：在平台里配置并等 HTTPS 证书签发（通常几分钟）
